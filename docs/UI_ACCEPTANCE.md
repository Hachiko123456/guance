# UI 与功能验收矩阵

## 规则

- offscreen QML 测试不能代替 Windows 实机；
- 每个按钮必须有信号消费者和可观察结果；
- 不允许自动点击、自动出牌、真实采集或系统代理副作用进入普通 UI 测试；
- 任何未执行的实机项标记为“未验证”。

## 自动化矩阵

| ID | 动作 | 预期 |
|---|---|---|
| UI-001 | 开始使用 | 打开授权流程或进入已授权启动流程 |
| UI-002 | 未勾选授权 | 同意禁用，取消不改变配置 |
| UI-003 | 勾选授权 | 发出 `consent=True`，进入准备状态 |
| UI-004 | 停止并恢复网络 | 先恢复代理，再停 helper，清空建议 |
| UI-005 | 离线演示 | 明确显示离线状态，不启动采集 |
| UI-006 | 退出演示 | 清除演示牌局和建议 |
| UI-007 | 打开浮窗 | 唯一浮窗显示，重复操作幂等 |
| UI-008 | 关闭浮窗 | 浮窗隐藏，`floatingVisible=False`，主窗口恢复 |
| UI-009 | 其他候选 | 展开/收起不改变候选数据 |
| UI-010 | 导入模型 | 选择路径后发出路径，取消无副作用 |
| UI-011 | 移除授权 | 二次确认，取消不执行 |
| UI-012 | 修复网络 | 发出 repair，显示结果 |
| UI-013 | 导出诊断 | 只导出脱敏有限记录 |
| UI-014 | 顶部导航 | 助手、设置、诊断切换正确 |

## 核心验收

保留既有 CORE ID。以下是待证明的要求，不是本次已通过结果；历史“73 动作”“47 个快照”等数字没有附本次可复核证据，不作为发布通过声明。

| ID | 目标 | 必须证明 |
|---|---|---|
| CORE-001 | 历史与实时解析 | 对声明支持的格式跑通解析到状态；历史接口缺口未修复时该能力不得标通过 |
| CORE-002 | 状态版本 | 确认动作递增状态版本，迟到推荐丢弃 |
| CORE-003 | 真实模型 | 真实权重可加载并记录 SHA-256；固定公开快照产生合法候选 |
| CORE-004 | 模型进程 | 加载失败、超时、崩溃可报告且不静默回退 |
| CORE-005 | direct | 无上游配置可构建，真实切换需授权并验证恢复 |
| CORE-006 | upstream | 支持的 HTTP/mixed 配置正确，凭据不进入命令/日志 |
| CORE-007 | 证书 | consent=False 不触发安装/删除，作用域与实机授权正确 |
| CORE-008 | 诊断 | 有界、脱敏、用户主动导出 |
| CORE-009 | 恢复 | helper ready 前不接管，停止时恢复先于 helper 退出，异常无残留 |
| CORE-010 | 打包 | 完整 onedir 的引导、GUI/QML 和退出分别通过 smoke |

## 实机与交付

Windows 10/11、100/125/150/200% 缩放、多屏、无代理和 HTTP/mixed upstream 组合必须在授权测试机上单独记录。真实牌局至少覆盖前 20 个确认动作、完整结束和新一局；由用户操作游戏，比较 UI/模型输入与离线解析的一致性。关闭/重启后核对无残留代理和 helper。

协议、状态、模型、安全和发布门槛以 [ACCEPTANCE_STANDARD.md](ACCEPTANCE_STANDARD.md) 为准。UI-001..014 与 CORE-001..010 均需实际证据；未执行、失败或接口缺口必须保留，不能用 offscreen 或文档更新替代实机验收。
