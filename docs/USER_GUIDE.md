# 用户使用说明

## 使用前

Guance 是开发版建议工具，不会替用户点击或出牌。真实采集会涉及当前 Windows 用户的证书和代理状态；只有在你理解授权说明后才继续。

## 首次启动

1. 启动 `Guance.exe` 或 `python -m guance`。
2. 阅读授权说明。
3. 未勾选同意时，取消或关闭都不会安装证书、切换代理或启动采集。
4. 同意后等待状态进入“等待游戏连接”。
5. 进入支持的牌局后，等待完整发牌和座位确认。
6. 只有状态可信且轮到本人时，建议区域才会显示候选。

实际出牌必须由用户在游戏内完成。建议不会自动点击，也不会替用户选择候选。

## Demo 与真实运行

离线 Demo 只适合查看 UI 和状态展示。当前 CLI `--demo` 参数的解析与 GUI 消费存在版本差异，不能以命令行参数本身保证隔离演示；请以界面中的明确演示入口和测试结果为准。`--frozen-smoke` 是包验收用的有界无网络入口，不是用户演示模式，也不能证明真实模型推荐显示。

真实运行前确认：

- 模型文件路径正确且可以加载；
- 采集 runtime 已准备；
- 当前代理状态允许恢复；
- 你有权读取自己的授权环境；
- 你知道停止按钮会先恢复原代理。

## 离线评估包

由当前源码构建的 fresh no-capture 评估包只用于本地离线评估：

- 不包含采集 helper，界面会显示采集组件不可用；不会回退到系统 mitmproxy。
- 默认 FableDan（NumPy）可加载并给出候选；MARVEL/Torch 不在包内，明确
  unavailable/fail-closed，不会切换成 FableDan 或别的 checkpoint。
- 不包含自包含 GPU 支持；需要 GPU 时使用 [离线交付手册](OFFLINE_DELIVERY.md) 中的
  源码 + 隔离 CUDA 环境。
- `production_ready=false`、`strength_claim=false`，候选分数不是胜率。
- `REDISTRIBUTION_NOT_AUTHORIZED`：不要上传或转发包与权重。

## GPU 与 CPU

默认设备策略为 `auto`：有可用 CUDA 且真实探测成功时使用 GPU，否则使用 CPU 并在
设置页显示原因。可用 `GUANCE_MODEL_DEVICE=cpu|cuda` 强制。设备回退不是模型回退；
强制 `cuda` 在无设备时明确失败，不会偷偷改用 CPU。详见
[GPU 推理](GPU_INFERENCE.md)。

## 日常状态

| 状态 | 含义 |
|---|---|
| 等待游戏连接 | 采集已准备，尚未看到目标牌局连接 |
| 已收到牌局 | 收到发牌，正在等待首家/座位证据 |
| 对局已同步 | 状态通过当前校验，可以进入推荐流程 |
| 正在计算 | 本地模型正在计算候选 |
| 需要处理 | 结构、网络、模型或状态校验失败 |
| 本局已结束 | 当前局面已清除，等待下一局 |

## 停止和恢复

点击“停止并恢复网络”。正确顺序是恢复代理、停止 helper、关闭模型 worker。证书材料默认不会自动删除；删除授权是设置中的独立操作，需要再次确认。

本地待合并版本增加了运行租约和启动恢复；已提交基线不能承诺自动完成崩溃恢复。发现网络异常或代理冲突时停止使用采集，先查看诊断，不盲目覆盖其他程序的设置。

## 浮动窗口

浮动窗口只是同一牌局的另一个视图。产品验收要求关闭浮窗时返回主窗口而不停止会话，停止助手时恢复网络，退出应用时完整清理。本地浮窗修复尚未随此次文档提交发布，实际关闭、尺寸和退出清理仍需按对应版本验证。

## 常见问题

### 一直等待连接

确认已进入真实牌桌而不是大厅或未开始页面。若刚重新授权，关闭并重新打开目标小游戏后再试。仍失败时打开诊断页查看 `HELPER_START_FAILED`、`protocol_rejected` 或 `frame_dropped` 原因。

### 没有建议

可能是还没轮到本人、座位尚未确认、模型未加载、公开动作无法唯一解释，或当前状态已过期。不要根据“没有建议”自行推测牌局正确性。

### 需要导出诊断

使用设置/诊断页的导出功能。导出包只包含脱敏结构化记录，不会自动上传。分享前仍应自行复核内容。

## 安全提醒

不要把 `*.mitm`、证书目录、模型权重、完整日志或包含账户信息的文件上传到 issue、聊天或公共仓库。完整安全边界见 [SECURITY.md](SECURITY.md)。
