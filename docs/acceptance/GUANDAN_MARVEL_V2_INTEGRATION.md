## 4. 当前/目标架构、对象所有权和迁移裁决

### 4.1 采用的增量架构

```text
capture / protocol
    -> SessionEngine / GameState
    -> versioned immutable public+self state + confirmed event history
    -> Controller
    -> ModelService
    -> ModelClient / InferenceClient
    -> bounded JSONL worker
    -> ProviderRegistry / ModelFactory
       -> fabledan (保留)
       -> guandan / builtin.guandan 0.1 scaffold (保留)
       -> guandan_marvel_v2 (新增且独立)
          -> strict bundle/identity parser
          -> restricted weights_only loader
          -> public+self adapter
          -> structured action-row decoder/executor
          -> four-observer history/KV session
          -> lazy optional Torch/MARVEL/native runtime
    -> CanonicalAdviceResult
    -> ViewModel / QML
```

- application root 负责组合；ModelService 管 selected source/client 生命周期；InferenceClient 管 bounded worker、request/epoch/generation 与失效；worker 持有一个 provider session；V2 provider session 持有 runtime、confirmed history、speculative branch 与 KV cache。
- domain、contracts、Controller、ViewModel、QML 不持有 tensor、Torch 或 native 对象。旧 v1 public view 不静默扩义；后续新增明确版本的 public+self DTO。
- `guandan_marvel_v2` 不借用或覆盖 `guandan` / `builtin.guandan` 的 0.1 compatibility policy。默认 FableDan-only import/start 不导入 Torch、MARVEL 或 native extension。
- 裸 `.pt` 不推断 provider；只接受显式 bundle/manifest。hash、schema、algorithm、architecture、iteration、classification、protocol、config/source/backend identity 任一缺失或错配即 fail closed。
- 阶段 1 仅证明隔离 checkpoint/runtime synthetic CPU demo；不能据此宣称 live public+self 可用。当前 Guance 缺 phase、declaration、previous-result、exchange、wildcard、token history/counters 和精确四 observer history 时必须 unavailable/unsupported。
- 四 observer 的 actor 输入仍只允许 public+self：公共 commit 投影到四个信息集，私有 self prefix/exchange 只进入所属 observer；不得复制本人 observer、构造对手手牌或用 PAD/零值替代未知历史。
- “previous outcome”仅指当前决策前已公开、具时序来源的上一局结果摘要；当前局 future/post/outcome/reward/settlement label 永不进入模型输入。
- `experimental`、`test_only`、`production_ready` 分开表达：真实但未正式评估的 runtime 可为 experimental；fake/synthetic runtime 必须 test_only 且不得进入默认生产 registry/package。阶段 1–6 固定 `production_ready=false`、`strength_claim=false`。
- Windows `.pyd` 身份必须按真实 Windows build 独立记录；不得伪造为 Linux `.so` identity。是否语义等价留给阶段 5 golden/differential gate。
- 不采用 WSL/Linux sidecar、独立服务、ONNX/TorchScript 或部署模型变更；若后续证明必须采用，触发重大暂停条件。
